# ADR-008 · S-08 · Tìm kiếm Toàn văn bản Tiếng Việt Không Dấu (pg_trgm & unaccent)
- Trạng thái: Đã chốt
- Người viết: TV4
- Liên quan: C-02, C-23 · FR-SRCH-001, CONS-006, 3.4 · CR-08

## Bối cảnh
SRS v1.0.0 mô tả cú pháp ToTsQuery("vietnamese", ...) không tồn tại mặc định trên PostgreSQL 16 (lỗi C-02). Sử dụng ILIKE thông thường sẽ bị Full Table Scan gây chậm khi dữ liệu lớn và không xử lý được trường hợp gõ thiếu dấu/sai dấu nhẹ.

##  Quyết định
Phương án B — Trigram Matching + Unaccent trên PostgreSQL 16:
- Raw SQL Migration kích hoạt 2 extension: unaccent và pg_trgm (bổ sung ngoại lệ cho CONS-006).
- Tạo hàm bọc f_unaccent chuẩn IMMUTABLE PARALLEL SAFE:
  CREATE OR REPLACE FUNCTION f_unaccent(text)
  RETURNS text AS 10
    SELECT public.unaccent('public.unaccent', )
  10 LANGUAGE sql IMMUTABLE PARALLEL SAFE;
- Tạo cột SearchText (Generated Stored) trên Recipes: lower(f_unaccent("Title" || ' ' || "Description")).
- Tạo GIN Trigram Index: CREATE INDEX "IX_Recipes_SearchText_Trgm" ON "Recipes" USING gin ("SearchText" gin_trgm_ops);.
- Query GET /api/v1/recipes/search?q=: Làm sạch q (bỏ dấu, chữ thường). Yêu cầu q >= 2 ký tự (nếu < 2 trả 422 SEARCH_QUERY_TOO_SHORT). Lọc bài Status == Published và IsDeleted == false. Sắp xếp theo độ tương đồng trigram, ưu tiên khớp Title.

## Hệ quả
- Tìm kiếm tiếng Việt không dấu, có dấu, viết hoa/thường hay sai dấu nhẹ đều trả kết quả chính xác trong < 100ms.
- Cột SearchText làm tăng nhẹ dung lượng đĩa CSDL PostgreSQL.

## Phương án dự phòng
Nếu từ khóa q chứa ký tự đặc biệt hoặc gây lỗi syntax query: Backend tự động dùng Regex.Replace loại bỏ ký tự lạ và đưa về chữ thường trước khi truyền vào EF Core ILike.
