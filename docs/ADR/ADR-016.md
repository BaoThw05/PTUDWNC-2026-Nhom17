## Bối cảnh
SRS v1.0.0 đưa ra chỉ số NFR quá nặng so với quy mô đồ án sinh viên 6 tuần (p99 <= 1000ms cho mọi tác vụ kể cả upload ảnh 5MB, tính sai SLA 99.5% uptime thành 3.65h, đòi hỏi OpenTelemetry/Grafana ngay từ đầu).

## Quyết định
Phân chia NFR thành 2 tầng rõ ràng:
- Tầng NFR Base (Bắt buộc hoàn thành trước 01/11/2026):
  - SLA Uptime: Đính chính SLA 99.5% Uptime ≈ 43.8 giờ downtime/năm.
  - API Response Time: p50 <= 150ms cho GET cached APIs, p95 <= 500ms cho tác vụ Ghi/Write. Đo bằng k6 load test (50 VUs trong 5 phút trên demo).
  - Core Web Vitals: LCP <= 2.5s, CLS <= 0.1. Google Rich Results Test xanh 100% cho JSON-LD Schema.org Recipe.
  - Observability Base: Serilog ghi JSON ra Console/Seq, gán X-Correlation-ID. Probe /health/ready chỉ kiểm tra kết nối PostgreSQL.
- Tầng NFR Mở rộng (Định hướng phát triển sau 01/11/2026):
  - OpenTelemetry Distributed Tracing sang Jaeger/Grafana Tempo.
  - Test coverage > 80%, SonarQube static analysis, Kubernetes auto-scaling.

## Hệ quả
- Nhóm tập trung 100% nguồn lực hoàn thiện sản phẩm chạy thật ổn định đúng mốc 01/11/2026.
- Kết quả đo đạc NFR Base được xuất bản chính thức trong file docs/bao-cao-do-nfr.md.
